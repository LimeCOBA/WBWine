# WB Wine

Система распределяет посылки по расписанию перевозчика с учётом свободного места на нодах и в машинах. Семь отдельных Django/React-кабинетов обращаются через ORM к одной базе SQLite, `wbwine.sqlite3`. Atlas и Wild также доступны как чистые Python-модули в `domain/`. При первом запуске создаются схема и группы доступа. Тарифы, сеть, упаковку, людей и рейсы вводит оператор.

## Запуск на Windows

Из корня проекта (Python 3.12 и Node.js):

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
npm.cmd ci
npm.cmd run build
.venv\Scripts\python.exe manage.py migrate
.venv\Scripts\python.exe manage.py createsuperuser
.venv\Scripts\python.exe run.py
```

Команда createsuperuser нужна один раз. Администрирование доступно на http://127.0.0.1:8102/admin/. Пользователь открывает /register/ нужного кабинета, задаёт логин и пароль и сразу входит. Каждая регистрация создаёт отдельный логин с одной ролью. Для всех ролей кроме продавца verify_application в ledger/registration.py возвращает копию заявления. Это имитация допуска, в том числе для редактора общих тарифов Wild. Администратор заводит упаковки и назначает сотрудников и водителей на конкретные ноды и машины. Служебный секрет генерируется локально, файл .local-secret исключён из Git. Стенд слушает loopback и использует HTTP. Для общей установки нужны HTTPS, защищённые cookie, управление секретами и резервными копиями.

## Как провести первую реальную отправку

1. В Partner владелец вводит адреса, полную ёмкость и фактически занятый внешними грузами объём. Отметьте РЦ, если нужен базовый вариант. В администрировании назначьте работников созданным нодам.
2. В Fleet перевозчик вводит машину и её ограничения. Администратор связывает машину с пользователями группы drive. Перевозчик указывает плечо, водителя, будущие времена отправления и прибытия, тип рейса и цену. Для попутного груза введите добавочные рубли на заказ. Для отдельного — стоимость всего рейса. Время в интерфейсе московское.
3. В Wild введите тариф с началом действия не позднее текущего момента. В Seller укажите узлы, заказ, упаковку, размеры, массу, срок доставки и ожидаемое хранение на выдаче. «Рассчитать» показывает прогноз. «Оформить» повторяет расчёт по текущему состоянию и резервирует все ноды и места на выбранных рейсах одной транзакцией.
4. Сотрудник начальной ноды подтверждает приёмку. При наступлении времени рейса водитель подтверждает забор, затем передачу. Следующее плечо открывается после передачи предыдущего. Нода назначения выдаёт груз. При заборе освобождается резерв в ноде отправления, при выдаче — в конечной ноде. История плеч сохраняется.
5. Для проверки пика измените внешнюю загрузку транзитного узла в Partner и повторите расчёт следующего заказа. Изменение допускается только в пределах ещё свободной ёмкости.

## Расчёт

Для упаковки с размерами в сантиметрах Vbox = длина × ширина × высота / 1000 литров. Занимаемый объём V = Vbox × (1 − l × (1 − k)), округление вверх до 0,001 л. k — доля физического объёма, l — достигаемая укладываемость. Коробке соответствует k = 1.

Berry — единица цены хранения WB Wine. Эталон: при ставке b = 1 хранение 1 эффективного литра в течение суток стоит 1 Berry. Для отправления B = b × V × T. Время T включает ожидание отправки, пересадки и хранение до выдачи. Сумму за хранение в рублях даёт B × курс ₽/Berry. Перевозка оплачивается отдельно: a × сумма цен рейсов в рублях. Обработка и риск добавляются за каждое плечо. Денежные составляющие округляются до копеек.

Atlas перебирает простые пути по будущим рейсам. Проверяет пересадки по времени, срок доставки, массу, эффективный объём и доступность каждого узла. Вместимость машины уменьшается на уже забронированные посылки. Отдельный рейс обслуживает один заказ. Из допустимых цепочек выбирается минимальная по полной стоимости, при равенстве — самая ранняя по прибытию, затем по идентификаторам рейсов. Тем же алгоритмом вычисляется минимум с обязательным посещением РЦ. Когда подходящей цепочки через РЦ нет, экономия относительно него неопределена.

## Рабочий словарь данных

| Сущность | Смысл и связи |
|---|---|
| User, Group | Учётная запись и роль. Владелец, продавец и перевозчик пока представлены аккаунтом оператора. Водитель назначается машине, работник — ноде. |
| Node | Владелец, работники, адрес с населённым пунктом, признак РЦ, доступность, ёмкость, внешний занятый объём. Город выбирается из автономного дорожного графа Atlas. |
| Packaging | Именованный тип упаковки с коэффициентами заполнения и укладываемости. |
| Vehicle | Перевозчик, допущенные водители, госномер, литры, килограммы. |
| Trip | Одна направленная поездка между двумя нодами, машина, водитель, расписание, цена и признак отдельного рейса. Пересекающиеся назначения отклоняются. |
| Tariff | Ставки и момент начала действия. Для новой оценки выбирается последняя вступившая в силу запись. |
| Parcel | В этой версии один заказ содержит одну посылку. Номер уникален у продавца. Сохраняются описание содержимого, упаковка, габариты, масса, обещанный срок, конечные ноды, снимок расчёта, приёмка и выдача. |
| Transfer | Назначение посылки на рейс с порядком плеча и фактическими отметками забора и передачи. |
| Reservation | Резерв места на узле для конкретной посылки и время освобождения. Свободно = ёмкость − внешний занятый объём − активные резервы. |

Разделение заказа, товарной позиции и посылки понадобится для частичных отгрузок. Реестры юрлиц и регионов, персональные данные покупателя, возвраты и бухгалтерские проводки в текущую схему не включены. Резерв пути консервативный — литры на будущих узлах удерживаются с момента оформления. Перебор рассчитан на локальный пилот с небольшим расписанием. Старая демобаза предыдущей реализации сохранена как legacy-demo.sqlite3.backup и отключена.

## Проверка

```powershell
.venv\Scripts\python.exe manage.py test ledger
.venv\Scripts\python.exe manage.py check
.venv\Scripts\python.exe manage.py makemigrations --check
```

Модульные тесты проверяют литры, коэффициенты, Berry, рубли и выбор цепочки. Интеграционные тесты поднимают отдельную временную БД и проверяют работу через API, включая загрузку справочников, назначения, резерв, выдачу, конфликт повторного заказа, принадлежность объектов и CSRF.
Дорожная модель, оба метода транспортного планирования, контрольный пример и границы реализации описаны в [документации Atlas](ATLAS.md).
